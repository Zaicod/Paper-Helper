# 多关键词与匹配方式设计

状态：用户已确认交互、逐词匹配方式，并确认增加 Crossref 备用来源，进入实施。

## 推荐交互

搜索页提供关键词输入、匹配方式选择（精准匹配 / 模糊匹配）和“添加关键词”按钮。回车等同添加，中文输入法组词期间不触发。每次添加一个完整关键词或短语，不按空格拆成多个列表项。

已选关键词显示为有序标签列表，例如 `[multimodal learning · 精准 ×] [retrieval · 模糊 ×]`。逐项删除，也可清空；列表内的匹配方式有明确文字，不仅靠颜色。最多 10 项，去除首尾空白并忽略大小写去重；重复添加时提示，不静默重复。总关键词文本沿用 500 字符上限。

每个词单独保存匹配方式，支持两种方式混合。点击搜索时如果还有未添加的非空输入，按当前方式加入再搜索，避免漏掉输入。列表为空时不请求上游。添加、删除或清空后视为新查询，重新搜索从第 1 页开始；旧结果保留但不能继续沿用旧条件翻页。

## 匹配语义

- 精准匹配：将该关键词作为完整短语交给来源检索；例如 multimodal learning 按短语处理，不代表论文标题或整个摘要必须完全等于这串文字。
- 模糊匹配：采用较宽泛的分词/普通文本检索，不要求完整短语连续出现；不承诺拼写纠错、任意子串、同义词扩展或自动翻译。
- 多个已选关键词默认同时满足（AND）。单个模糊关键词里的词按来源支持的普通文本规则组合。页面明确提示这些规则，避免将多个词整体当成一个精准短语。
- arXiv 与 OpenAlex 均由 Python 适配器分别构造合法查询，转义引号与来源查询操作符，关键词本身不能注入查询结构。

## 方案取舍

推荐逐个关键词保存方式，列表中可看见差异，满足混合查询。另一方案是全局统一精准/模糊开关，更简单但不能区分列表中不同词的模式。本期不引入词库或 AI 关键词推荐，以手工添加实现多选。

## 接口与兼容

Vue 发送结构化关键词数组（text、match_mode），Java 使用 DTO 接收并验证数量、长度、去重与模式；Controller → Service → ServiceImpl 分层保持不变。Java 将结构化条件转交 Python，Python 编译为来源查询。旧单 query 调用继续有效，避免破坏已有研究任务和脚本。

结果回显实际关键词列表及模式；分页、排序、实际来源固定、收藏夹与报告功能继续沿用现有链路。翻页保留完整关键词条件和来源，不丢失匹配模式。

## 已确认的备用来源补充

本次真实请求 OpenAlex429、Semantic Scholar429、Crossref200。用户确认增加 Crossref。Crossref 支持按 is-referenced-by-count 排序，但引用数口径仅为 Crossref 收录，摘要与 PDF 可能缺失；页面明确提示。Crossref 普通查询不保证精准短语或 Boolean AND，不冒充这两种能力：包含精准关键词时不能使用 Crossref，自动引用排序也不会将精准查询降级回退到 Crossref。全为模糊词时可回退 Crossref，并显示其按相关度匹配的限制。其他来源仍保持 AND 语义。

## 验证

前端覆盖添加、回车、中文输入法、空白/重复/超限、删除/清空、混合模式显示、未提交输入处理和条件变化重置分页。Java 验证 DTO 和旧查询兼容；Python 在受控 HTTP 边界检查两个来源收到的精准/普通文本表达式、引号转义及 AND 组合。浏览器覆盖新增两项、删除一项、混合检索、排序与翻页；测试不以外部站点实时命中数量作为稳定断言。
