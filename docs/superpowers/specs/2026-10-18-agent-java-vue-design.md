## 1. 目标与方案选择

目标是通过同一个可运行项目，学习 Java 业务后端和 Python Agent 开发，并逐步将 React 页面替换为 Vue。

| 方案 | 收益 | 成本 | 选择 |
|---|---|---|---|
| 渐进拆分：Vue + Java 业务服务 + Python Agent 服务 | 复用现有 Agent 能力，能分别练习业务与 AI 工程，每阶段可验证 | 需要明确服务接口和数据归属 | 推荐 |
| 全部迁移到 Java | 统一后端语言，可以专注 Java AI 生态 | 现有 Python Agent、RAG 和工作流需要重写，同时学习范围扩大 | 当前不采用 |
| 仅将 React 改为 Vue | 可以较快学习 Vue，后端变化小 | 无法覆盖 Java 后端学习目标，现有流程问题仍存在 | 不作为完整改造方案 |

## 3. 目标边界

| 部分 | 职责 | 数据责任 |
|---|---|---|
| Vue 前端 | 登录、收藏夹、笔记、研究任务、报告与证据展示 | 通过 Java 接口读写业务数据 |
| Java / Spring Boot | 用户权限、论文资料、收藏夹、笔记、公开任务状态与最终结果 | 业务数据唯一写入方 |
| Python / FastAPI | 搜索适配、PDF 解析、RAG、模型调用、研究执行与评估 | 保存内部执行状态、证据索引和运行审计 |

迁移完成后的调用链：Vue → Java → Python → Java 保存结果 → Vue 展示。

Java 的公开任务状态是 Python 执行状态的业务投影。Python 上报或返回执行状态，Java 完成校验和幂等保存；两个服务不直接更新对方的表。

迁移期间按模块切换数据归属。一个模块由 Java 接管后，Python 旧业务写接口退出使用，避免同一业务表被两个 ORM 同时维护。Python 的研究与检索接口继续保留。

## 4. 技术选择

- 前端：Vue 3、Vue Router、Pinia、Vite；沿用 TypeScript，迁移时复用 API 字段类型。Vue 并不要求 Java 后端。
- Java：项目单独配置 JDK 21，使用 Spring Boot、Maven Wrapper、Spring Security、MyBatis、MySQL。按用户明确选择，使用黑马常见的单模块三层结构、Service 接口与实现、DTO/VO 与 Result；早期 JPA 已在第三阶段替换。Wrapper 固定项目构建方式，首次使用仍需下载依赖。
- Redis：复用为 Java 登录会话存储；内部任务数据库是任务状态事实来源，Redis 不作为唯一任务记录。
- Python：保留 FastAPI、Pydantic、OpenAI Agents SDK、HTTPX、pypdf、现有 RAG 和评估模块。当前阶段以已有 ResearchWorkflow 为正式执行内核。
- LangGraph：先保留离线学习入口；完成行为一致性验证后再承接正式编排，并增加条件分支与检查点。
- 首版 Java 与 Python 通过 HTTP/JSON 通信。先用轮询实现状态查询，稳定后再迁移现有 WebSocket 进度展示。

当前 Spring Boot 官方系统要求至少 Java 17，因此默认 JDK 8 不能直接用于新服务。JDK 21 作为本项目的选择，按项目配置，不替换其他项目的默认 JDK。

参考：

- [Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)
- [Vue 官方创建项目说明](https://vuejs.org/guide/quick-start.html)
- [LangGraph 持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)

## 6. 分阶段改造与验收

### 阶段 0：建立可复现运行基线

工作：补 Python 安装配置与启动说明，区分核心、网页和 MCP 依赖；记录离线验证命令。为新 Java 项目配置 JDK 21 和 Maven Wrapper。先保留旧启动方式。

学习：依赖管理、项目级 JDK 配置、环境配置与可复现运行。

验收：新环境能按文档安装并运行离线研究；网页缺少数据库或 Redis 时能给出清晰配置错误；Java 服务能独立启动。真实模型密钥通过环境或受保护设置提供，不写入仓库。

### 阶段 1：统一 Python 研究执行能力（首个实施子项目）

工作：网页与命令行通过同一应用服务调用现有 ResearchWorkflow，接通真实检索或可信收藏论文、RAG、证据判断、重试和失败隔离。增加结构化阶段事件，并修复报告文件名。

学习：依赖注入、异步并发、上下文构建、证据判断、错误分类与服务边界。

验收：同样的输入与离线替身，在两个入口产生同样的论文集合、成功失败数量和证据审计；一篇失败不会丢失另外两篇结果；含 Windows 特殊字符的主题可以生成三个报告文件；真实模式不隐式退回演示数据或演示分析。

### 阶段 2：Java 接管用户与资料管理

工作：按用户 → 收藏夹 → 笔记的顺序迁移。使用 Spring Security、会话、参数校验、JPA 和事务。收藏夹、笔记、任务带 owner_id，所有查询和修改以当前登录用户为边界。论文元数据可共享，用户收藏与笔记独立。

学习：权限与资源归属、事务边界、数据库关系、分页和统一错误响应。

验收：用户 A 和 B 可以有同名收藏夹；B 无法读取、修改或删除 A 的私有资源；未登录请求被拒绝；一项操作失败时关联写入回滚。

已有全局收藏夹不自动认定属于某个用户。迁移工具保留原数据快照，只迁移明确指定归属的数据。

### 阶段 3：打通 Java 与 Python 的研究任务

工作：Java 校验用户资源后创建持久化任务，生成 task_id，以相同 task_id 向 Python 提交可信论文和研究选项。Python 快速返回受理结果，后台执行，Java 查询执行状态并保存最终报告。初版使用单个 Python 执行进程和持久化执行记录。

学习：服务调用、异步任务、超时、幂等、状态机和故障恢复。

验收：重复提交同一 task_id 不会重复启动模型调用；Java 调用超时后使用相同 task_id 查询或重试；用户只能查询自己的任务；进程重启后可查询历史状态。首版将失去执行进程的运行中任务标记为 interrupted，明确需要重试，不宣称自动续跑。

失败分为提交失败、证据不足、单篇分析失败、全部分析失败和报告保存失败。部分论文成功时保留结果并显示失败数量；全部失败时任务失败。

内部执行接口只供 Java 服务调用，验证服务身份。前端不直接调用 Python。个人模型凭证迁移单独处理，在验证完成前不切换原设置功能，也不通过浏览器传递明文密钥。

### 阶段 4：深入 Agent 工具调用与 LangGraph

工作：让分析 Agent 在需要时调用受限的证据检索工具。先将现有“分析 / 补充检索 / 证据不足”判断形成清晰状态，再加入条件边与检查点。复用阶段 1 的分析、重试和上下文服务。

默认边界：每篇初次判断后最多两次补充检索；每次模型调用设定超时；超过检索次数或仍无证据时返回 insufficient。暂态网络错误才重试，验证错误和明确证据不足不盲目重试。

学习：工具 schema、工具权限、条件路由、状态恢复、停止条件和调用成本控制。

验收：准备证据充分、补充后充分、始终不足三类固定案例，分别走到预期分支；工具调用次数有界；恢复流程不重复已完成的有副作用操作。检查点与 thread_id 的使用按持久化方案实测。

### 阶段 5：逐页迁移 Vue

顺序：登录 → 收藏夹与笔记 → 研究任务 → 报告与证据 → 模型设置。

学习：组件、路由、状态管理、接口类型与异步页面状态。

验收：先完成“登录 → 收藏论文 → 发起研究 → 查看结果”的完整路径，再逐页补齐其余功能。显示真实的运行阶段、失败原因和证据来源，不将模拟数据包装成真实结果。

### 阶段 6：建立 Agent 评估基线

工作：先固定至少 10 个带参考证据的案例，比较仅摘要、摘要 RAG 和 PDF RAG。记录模型、提示词版本、检索配置、延迟、模型 token 用量和费用估算，保留人工评分。

学习：对照实验、引用准确性、错误归因和成本与质量权衡。

验收：每项指标有定义与分母，失败案例可追踪；能说明哪些改动改善结果、哪些增加成本。chunk_id 合法性与“该证据确实支持结论”分别评估，不将前者等同于后者。没有实测数据时不写效果提升百分比。

## 7. 阶段 1 的具体文件与接口设计

保留正式执行内核 `paper_agent/workflows/research.py`。新增 `paper_agent/services/research.py`，为网页与命令行提供共同入口，并集中选择 demo/live、证据配置与阶段回调。

`ResearchWorkflow.run` 保留原有 topic、limit、category 参数，增加可选的可信论文列表和异步事件回调。已有调用方式兼容。传入论文列表时跳过搜索，不在编排层直接读取收藏夹或数据库。

职责分配：

- `core/models.py`：增加可序列化的研究阶段事件；保留既有 ResearchReport 与 ContextAudit。
- `services/research.py`：创建并调用正式工作流，明确 demo/live 模式，不直接操作 HTTP 请求。
- `workflows/research.py`：执行获取论文、证据索引、并发分析、综合和构思，发出阶段事件。
- `interfaces/cli.py`：解析命令行参数并调用共同应用服务；保持既有输出格式。
- `interfaces/web.py`：读取可信收藏论文后调用共同服务，订阅阶段事件，继续负责原有报告保存和网页任务状态。
- `interfaces/report.py`：生成跨平台安全文件名；仅将标题用于文件基名，清理路径分隔符、控制字符和 Windows 保留字符，空基名回退为 research。保留时间前缀及原始主题在报告正文中的显示。
- `workflows/research_graph.py`：继续用于明确的离线图演示；阶段 4 达到正式流程行为一致后再迁移。

阶段事件至少包含 stage、status、paper_id（可空）、message、timestamp。stage 使用 search、index、analyze、synthesize、ideate；外层渲染和保存继续使用 render、persist。前端进度映射同步更新，不能因新增 index 事件重复累计百分比。

输入约束：topic 去除首尾空白后不能为空；limit 与论文列表长度均限制 1—20；显式空列表报错，不触发默认搜索；收藏夹过大时由入口明确拒绝，并提示选择不超过 20 篇。

错误语义：搜索失败是获取阶段失败；单篇检索或分析失败写入 analysis_failures；全部分析失败是任务失败；综合或构思失败明确标注阶段；报告保存失败不能标记 completed。事件流不记录模型密钥、会话令牌或完整敏感输入。

测试边界：离线模式不联网、不调用真实模型、不消耗 API 额度。围绕成功路径、部分失败、全部失败、空列表、超量选择、RAG 审计、事件次序、特殊字符文件名和真实模式缺少配置建立行为测试。

## 12. 第三阶段实施与 Java 分层调整

Java 已新增持久化研究任务，检查用户归属、生成可信论文快照，以固定任务 ID 通过内部 HTTP 提交 Python。Python 复用正式 ResearchService 与工作流，使用独立 SQLite 执行账本后台执行；Java 轮询并保存阶段事件、最终报告和安全失败信息。重启可以查询历史，遗留执行明确标记 interrupted，不自动续跑。

按用户追加要求，所有 Java 业务模块已统一调整为黑马 Spring Boot 单模块结构：Controller → Service 接口 → ServiceImpl → MyBatis Mapper，分离 Entity、DTO、VO，显式返回 Result。Flyway 原有迁移保留，新增 V2 任务表，不删除旧数据。

同用户的并发幂等提交在短事务内按用户行锁串行检查，重复提交返回同一任务；内部响应包含大小限制与覆盖响应正文的总超时。Python 执行账本限制并发和待处理队列，独占账本进程锁防止多执行进程重复消费。

验证与运行范围见 [第三阶段学习说明](../../phase3-learning.md)；代码分层见 [黑马课程对照](../../java-architecture.md)。真实模型、MySQL/Redis 与 Vue 未作为本次离线闭环验收内容。

## 14. 论文搜索与收藏夹论文 CRUD（2026-10-19）

用户确认复用已有 arXiv/OpenAlex。已新增 Vue 搜索页、Java 已认证搜索接口及 Python 内部检索入口，复用现有适配器并区分空结果、来源故障和超时；自动模式只尝试真实来源。查询、服务凭证、响应大小和总超时在服务边界处理。

收藏夹论文新增单篇 GET/PUT；V3 在个人关联中保存元数据快照与编辑标记。共享论文身份字段固定，个人编辑不修改其他收藏夹；重复添加保留个人编辑和笔记，新研究使用提交时快照，旧任务与报告不被改写。

74 项 Python、34 项 Java、23 项前端测试以及构建通过。真实三服务浏览器使用明确标注的本地文献 HTTP 测试源验收搜索、收藏、查改删和再次研究，原 Vue 工作流回归也通过。真实 OpenAlex 搜索另行成功，当前网络访问 arXiv 超时；没有把受控来源测试当作官方 API 可用性证明。

使用与学习见 [论文搜索与 CRUD](../../paper-search-learning.md)。
