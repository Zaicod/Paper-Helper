# 任务调度可靠性：有限并发与重复派发防护

## 本轮目标与现状

用户已选择“边讲解边优化，重点学习 Java 后端与 Agent 协作”，并确认任务调度可靠性方向。

目前 `ResearchSynchronizer.tick()` 在调用线程中串行处理 `store.pending()` 返回的最多 50 个任务。`WorkerClient` 默认给每个 HTTP 请求 5 秒完整响应期限。单个慢请求会延后后续任务；整个循环的 `synchronized` 只保护串行入口，并不能直接作为异步任务的去重机制。

本轮成功标准：一个请求被阻塞时，其他可用并发槽位仍能完成同步；同一个任务在本次同步结束前不会再次被本实例派发；所有同步请求都受并发上限约束。

## 方案选择

采用固定上限的线程池与任务 ID 集合，数据库继续保存待处理任务。相比单纯缩短超时，这能让正常请求在慢请求存在时继续推进；相比消息队列，它适合目前单 Java 实例、单 Python worker 的部署方式，新增概念和运维成本较少。

## 调度与职责

1. 定时入口只负责查询、筛选及提交同步工作，提交后返回，不在调度线程等待 HTTP 完成。
2. 配置 `paperflow.worker.sync-concurrency`，环境变量 `PAPERFLOW_WORKER_SYNC_CONCURRENCY`，默认 4，允许 1～16，超出范围启动失败并给出配置提示。
3. 同步线程池最多运行配置数量的任务，不设置额外的内存等待队列。容量不足的任务保留在数据库，后续轮次重新读取，不标记失败。
4. 同一个 JVM 使用线程安全的任务 ID 集合。在提交前原子登记，在完成、异常、提交被拒绝时释放。检查和提交还需处理调度入口重入，保证不会超出容量。
5. 每个工作单元复用现有凭证解析、HTTP 交互和结果落库逻辑。读取和更新仍通过 `ResearchTaskStore` 的短事务完成，HTTP 请求位于事务外。
6. 任务开始执行前检查截止时间。已截止任务不向 Python 发送请求，按现有规则记录 `sync_deadline_exceeded`。
7. 单个任务发生异常不影响其他任务。预期通信故障沿用现有安全提示；未预期的运行时异常必须释放槽位并记录不含凭证、请求正文或异常正文的故障类型，等待后续轮次重试。

## 幂等、状态与凭证

- HTTP 超时不等于 Python 没有接受任务。后续仍使用相同 task ID；不创建新业务任务或新执行 ID。
- 保留 Python 幂等账本、Java 乐观锁和终态保护。进程内去重仅防止同步请求重叠，不代表任意故障下模型调用恰好一次。
- 只有 queued 任务派发时读取个人凭证。若凭证删除但先前 POST 可能已被接受，保留现有 GET 恢复逻辑，避免直接否定远端执行。
- 账号归属、任务快照、报告内容和失败任务重试接口继续使用现有契约；线程池不持有或缓存长期凭证。

## 容量与关闭

- 并发 4 指最多 4 个同步 HTTP 操作，不是最多 4 个 Python Agent 任务；Python 接受任务后独立执行。
- 仍沿用当前数据库的每批 50 条查询。成功或故障落库更新 `updated_at`，让后续轮次推进其他记录；本轮不承诺严格先进先出或账号公平调度。
- 容器关闭时先阻止新增提交，再中断正在等待 HTTP 的同步线程，并最多等待 10 秒释放。`InterruptedException` 保留线程中断标记，不把本地停止转成任务失败。
- 数据库中的 queued/running 任务由下一次启动继续使用同一 ID 同步。停止 Java 不等同于取消 Python 任务。
- 本轮只支持一个 Java 调度实例。多实例需要数据库租约或分布式协调，另立设计。

## 测试与验收

新增同步器行为测试，使用闩锁控制慢请求，避免依赖固定休眠时间：

1. 阻塞第一个请求，断言第二个请求能够完成并写回结果。
2. 填满全部槽位，再调用调度入口，断言实际请求数不超过配置值。
3. 一个任务仍在同步时重复触发轮询，断言该任务最多有一个在途请求。
4. 请求完成或抛出异常后，后续轮次能够继续调度，证明槽位与去重登记释放。
5. 容量不足时不写失败状态，释放容量后数据库中的任务能够被处理。
6. 已过期任务不调用 Python；运行时故障不会阻断其他任务。
7. 关闭后拒绝新增同步，等待中的请求收到中断，持久化任务不被误判失败。
8. 覆盖合法与非法并发配置及关闭生命周期。

现有 `PersonalDispatchTest`、`ResearchApiTest` 等同步断言需改为等待具体可观察结果，所有等待设置上限，不用任意延迟替代完成条件。

运行 Java 完整测试及打包；真实 Redis 集成测试按项目原有独立环境开关执行，跳过时明确记录。无需调用真实模型或重启日常服务。
