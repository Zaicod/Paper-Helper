# 研究任务分类、搜索与分页

## 目标
将研究任务页面改为三个可点击切换的列表，避免不同状态的记录混在一起；每页固定显示 10 条，允许搜索当前分类的全部记录。

## 分类与交互
- 进行中：queued（等待执行）和 running（正在研究），默认打开此列表。
- 未完成：failed（执行失败）和 interrupted（已中断），可进入详情查看原因和重试。
- 历史研究：completed（已完成），可进入详情阅读、下载报告。
- 三类互斥且覆盖当前全部任务状态。历史记录直接使用现有已持久化任务，不另建历史表，不删除已有记录。
- 搜索按研究主题进行不区分大小写的包含匹配，支持中文。输入后点击搜索或按回车提交；清空后恢复当前分类完整列表。
- 搜索和切换分类都回到第一页；URL 保存分类、搜索词和页码，刷新或从详情返回时保留列表位置。
- 每页 10 条，按创建时间倒序、任务 ID 倒序保持稳定顺序，显示总记录数、页数和上下页按钮。
- 各分类使用不同空列表提示，区分没有记录与没有匹配的搜索结果。
- 提供刷新按钮以获取最新状态。任务完成后，下次读取列表会归入历史研究。
- 快速切换时仅采用最新请求的结果；请求失败显示错误与重新读取按钮，避免旧分类结果冒充新分类。

## 方案选择
1. 推荐：在现有 Java Controller / Service / Mapper 中增加分类和主题筛选，再在数据库完成计数和分页。检索覆盖全部记录，保留现有单模块三层结构。
2. 仅在 Vue 中筛选：实现较少，但必须获取全部数据，否则搜索与总数不准确，不采用。
3. 单独建立历史表或页面：增加数据迁移和状态同步成本，目前不采用。

## 接口和兼容
扩展 GET /api/research/tasks，增加可选 category（active / unfinished / history）和 keyword 参数，列表页面 size 固定传 10。保留原有无分类请求的查询行为以兼容现有调用，接口默认 size 改为 10。

Controller 校验输入，Service 映射分类状态与整理关键词，MyBatis 使用绑定参数实现可选条件；查询列表和计数使用相同条件。搜索中的 %、_ 按普通字符匹配。查询始终限定当前登录用户，不返回其他用户记录。不修改 Python Agent 的研究执行过程。

## 验证
Java 验证三类状态边界、跨页记录、搜索后总数、中文及特殊字符、非法参数和不同账户隔离。Vue 验证切换分类、搜索与清空、每页 10 条、回到第一页、URL 恢复及请求竞态。运行相关后端测试、前端测试与构建。
