# PaperFlow 引用追踪 Agent 设计

状态：用户已确认；已完成本地实现、回归测试和受控跨服务/浏览器验证。未发布或重启现有服务。使用说明见 ../../citation-tracking-learning.md。

## 目标与方案比较

在现有 Java 任务系统、Python Agent 和 Vue 收藏流程上扩展引用追踪，让用户知道候选论文是从哪篇论文、哪种引用关系发现的。

1. 推荐：独立的引用追踪任务，从收藏夹选定论文出发，双向追踪一层，再根据研究问题筛选。范围明确、可重试、可展示发现路径。
2. 自动并入所有智能搜索：体验连续，但会增加每次搜索的耗时和调用，失败边界更难解释。后续可作为可选增强。
3. 引入 PaSa 全套模型和运行环境：具备专门的搜索架构，但依赖、模型和部署成本更大；第一版只参考其发现与筛选分工。

## 用户流程

- 收藏夹选择 1 至 5 篇种子论文，点击“引用追踪”。搜索结果可先加入收藏后使用此入口。
- 输入研究方向；为空时按选定论文的主题发现相关研究，使用确定的默认任务说明。允许选择参考文献、引用该论文的文献、双向，默认双向。
- 创建后台任务，沿用个人默认模型与当前任务的权限、幂等、状态同步和历史展示机制。
- 结果展示种子、追踪方向、候选相关性、标题/摘要依据、来源关系和覆盖缺口。候选支持加入收藏，再进入现有正文准备和全文研究流程。

## 数据与执行边界

- 新任务类型 citation_trace，已有 search/research/study_report 保持原语义；新报告类型 citation_report。
- Java 从当前账号的收藏夹读取种子论文快照，前端不能直接提交任意来源 URL 或冒充他人收藏编号。原输入重试保留种子与方向快照。
- Python 使用 OpenAlex 正式 API 查询引用关系。解析 OpenAlex work ID 或 DOI；仅有 arXiv 编号的论文通过明确标识映射，无法可靠匹配时跳过并说明，不按相似标题默认为同篇。
- 对种子 outgoing referenced_works 解析参考文献元数据；incoming 使用 cites 过滤获取引用它的论文。固定 API 来源，不跟随返回的任意接口地址。
- 每次最多 5 个种子，只追踪 1 层；每个种子每个方向最多取 20 条，合计最多保留 60 个去重候选，最终结果 1 至 20 篇。
- 整个任务最多 20 次来源请求、2 次模型调用、120 秒；响应字节数和单次请求超时均设上限。预算用尽明确返回覆盖受限，不能宣称已查全。
- 按规范 DOI、OpenAlex ID 和 arXiv ID 去重；排除种子自身；同一论文可保留多条发现路径。引用边必须来自来源响应，模型不能生成或修改引用关系。
- 相关性筛选复用当前模型配置与元数据依据校验。没有充分标题/摘要依据时标记待核实，不将引用关系等同于支持论文结论。
- 任一方向或种子失败不抹掉已完成的来源结果。429、超时、无法映射、缺摘要、截断均用可读提示展示。所有来源失败则任务明确失败，正常返回空结果与来源错误分开。
- 不下载 PDF、不自动运行作者代码、不保证公开全文可获得；后续全文研究继续使用正文准备检查。

## 组件和接口

- Java：ResearchTaskDTO 新类型与方向参数；Service 校验 1 至 5 个种子及归属；任务快照和原输入重试保留方向；任务结果读取识别新报告类型。
- Python：新增 core/citation_agent.py 报告契约、tools/citation_graph.py 固定来源适配器、services/citation_tracking.py 预算与去重编排；worker 添加任务分支与结果校验。
- Vue：收藏夹选择入口、种子/方向/研究问题表单、引用追踪报告组件，复用收藏操作和任务详情。结果链接遵循现有安全 URL 规则；账号变化使旧请求结果失效。
- 不添加数据库表，复用任务 payload/result JSON 存储；如查阅现有 schema 发现类型约束，再做最小兼容迁移。

## 验收

1. 使用受控 SEED-IV/SEED-VII 元数据，验证双向追踪、同论文多路径合并、排除种子，以及相关性证据不足时降级。
2. 验证循环关系不会导致递归扩散，5 个种子、候选数量、来源调用、模型调用和总超时限制生效。
3. 验证假 DOI、伪造 API 链接、来源身份不符不能形成有效引用边，日志和公开错误不泄露模型凭证。
4. 验证一个来源失败时保留另一方向结果，全部失败时不返回虚假的成功报告。
5. Java 验证跨账号收藏访问被拒绝、幂等重放不重复创建、旧任务与重试兼容。
6. Vue 验证入口、方向选择、提交、路径展示、加入收藏以及账号切换后的过期响应隔离。
7. 先观察新测试失败再实现；运行相关测试及完整回归、前端构建，并执行受控跨服务或浏览器流程。真实来源可用性与模型效果另行标注，不用离线测试替代效果评测。
