# 论文正文准备与默认分析主题

状态：用户已确认，已完成本地实现与验证。使用说明见 ../../paper-evidence-learning.md；未发布或重启现有服务。下文故障描述记录改动前的情况。

## 已核实的问题

用户报告 MMSTG-Net 创建研究时反复提示无法获取 PDF，并要求创建论文研究时默认分析创新点、架构、解决的问题、结果和局限。

本地 worker 账本的该次任务为 study_report，状态 failed，error_code=study_report_failed；其提交快照中 source=openalex，paper_id=W7131315593，page_url=https://doi.org/10.1109/jbhi.2026.3667946，pdf_url=null。这里没有记录任何个人密钥或笔记。StudyPDFLoader 在 pdf_url 缺失时立即抛错，因此此任务未进入正文下载或提取阶段，不能归因于模型能力或向量检索。

该 DOI 指向 IEEE 文献页面；本次通过浏览工具访问时得到 JavaScript 人机验证页。作者主页列出了该文并链接 DOI，当前核对未找到可验证的开放正文。不能据此断言一定付费，也不能把 DOI/摘要页当成 PDF。

创建表单目前允许缺少 PDF 的论文直接创建全文学习报告；失败重试复制旧论文快照，即使之后修改收藏资料，旧快照也不会自动修复。这两点导致用户重复执行无效任务。

## 方案取舍

1. 仅改提示与默认主题：改动少，但用户仍没有可用于分析的正文。
2. 正文准备流程 + 可上传已有 PDF + 默认主题（推荐）：先尝试查找公开正文，找不到时允许用户提供已获取的论文文件；执行前确认准备状态。
3. 自动退化成摘要报告：能返回内容，但无法可靠解释架构、消融和局限；只保留为用户主动选择的“摘要初读”，不冒充全文学习报告。

## 默认主题

针对收藏夹中选定的论文，在研究分析和学习报告入口自动填入：

> 请基于所选论文，分析研究背景与解决的问题、核心创新点、模型总体架构及各模块作用、实验设置与主要结果、局限性，以及可改进的方向。对正文未提供的信息明确标注，不补造细节。

- 默认可修改，并提供恢复默认按钮。
- 收藏夹/论文选择变化时保留用户手动写过的主题，避免异步加载覆盖输入。
- 不将这一通用分析指令用作外部论文检索词。没有选论文且选择按主题检索时，需要输入具体研究方向；页面明确区分“找论文的主题”和“读论文的分析要求”。
- 后端对已选论文且主题缺省的请求补全同一默认主题，避免直接 API 调用与页面不一致；搜索 Agent 的问题仍必须明确填写。

## 正文准备流程

1. 收藏夹与新建任务页显示各论文正文状态：待检查、已准备、缺少正文、下载失败或无法提取文本。不得把“有链接”直接等同于“正文可用”。
2. 提供“准备论文正文”：先检查已有私有文件/可复用证据，再尝试现有 PDF 链接；缺失或失败时，按已确认 DOI/OpenAlex ID 查找对应开放获取位置。
3. 只接受匹配同一论文标识的正式元数据，不按标题相似自动换成另一篇论文。候选链接仍经过现有 HTTPS、公网地址、重定向、大小和页面限制；不绕过订阅、登录或人机验证。
4. 找不到可用正文时显示两条清楚的出路：补充公开 PDF 链接，或上传已有 PDF。展示具体失败类型，而不是都提示改链接。
5. 缺少正文时不创建注定失败的全文学习任务；可以主动选择摘要初读，沿用现有 research/abstract 链路，明确不保证全文架构与实验细节。

## 本地 PDF 的交付边界

- 用户从本人收藏论文入口上传文件，Java 验证登录、资源归属、文件大小及 PDF 特征后生成不透明附件 ID；不接受用户提供服务器路径。
- 附件是账号私有资料，不放入公共论文记录或共享搜索缓存。相同论文在不同账号中的文件保持隔离。
- Java 与 Python 通过已认证的内部接口传输文件或受约束的附件引用；浏览器不能指定内部下载地址，工作进程不能读取任意本地文件。
- 沿用 25 MiB、最多 200 页及文本提取限制。加密文件和扫描件/OCR 不在本轮支持范围，分别提示无法解密或缺少可提取文本。
- 文件摘要、证据来源与版本保存到新任务快照。报告记录文件来源与页码，可回到本人附件查看，不把上传文件宣称为从 DOI 页面下载。

## 创建、失败修复与历史

- 正文准备产生受信任的准备记录；创建学习报告时只校验准备记录与论文/账号/版本，不在数据库事务内做网络下载或解析。
- 旧任务和旧报告继续保留原快照。补 PDF 后通过“修复资料后重新创建”读取当前本人收藏资料与正文版本，创建新任务，明确列出资料变化；现有“原输入重试”仍沿用原快照并解释其含义。
- 幂等重放不重复上传、准备或创建任务；模型凭证仍使用当前个人设置，并继续遵守现有身份、配额和限流。
- 本轮不自动重新运行用户已有失败任务，也不使用个人模型密钥做付费验收。
