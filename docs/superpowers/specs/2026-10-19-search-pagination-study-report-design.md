# 检索排序、分页与 Agent 学习报告设计

状态：用户已确认，进入实施。

## 目标与现有基础

保留 Vue → Java 业务服务 → Python Agent 的分工。Java 继续使用单模块 Controller → Service 接口 → ServiceImpl → MyBatis Mapper。复用现有登录、收藏夹归属校验、选中论文快照、异步研究任务、进度查询与历史记录。

新增两个相连的功能：按排序方式浏览多页论文并加入收藏夹；从本人某个收藏夹选择单篇或多篇论文，让 Agent 生成中文学习报告，在线查看并下载 DOCX。

## 可选方案

1. 推荐：来源端排序和分页，新增学习报告任务类型，复用任务基础设施。排序覆盖检索结果集，生成过程可追踪，已有研究任务行为保持兼容。
2. 简化：前端只排列已有的 10 或 20 篇，再把原研究报告转换成 Word。实现较少，但不能代表全部结果的排序，原报告也缺少模块解释和学习体会，不采用。
3. 独立报告服务与独立任务系统。隔离更强，但当前学习项目会多出重复的鉴权和任务维护成本，暂不采用。

## 检索排序与分页

- 增加排序选择：最相关、最新发表、引用最多，默认最相关。
- 分页来自上游 API，页面从第 1 页开始；每页支持 10、20 条，显示总匹配数、当前页及上一页/下一页。
- 查询词、来源、排序、每页数量变化后回到第 1 页。加载和请求序号保护防止旧响应覆盖新查询。
- arXiv 对应 relevance、submittedDate；OpenAlex 对应 relevance_score、publication_date、cited_by_count。排序方向由适配器按官方语义映射。
- 引用最多由 OpenAlex 提供；选择此排序时自动模式使用 OpenAlex，明确显示实际来源。手动选择 arXiv 时该排序不可选，并解释可切换到 OpenAlex。
- 引用数未知显示“暂无引用数据”，不能伪装为 0；arXiv 论文不补造引用数。
- 自动模式第 1 页可按支持能力回退。一旦开始翻页，后续页固定在实际来源，失败时显示该来源错误，避免第 2 页悄悄切站造成重复或漏页。
- 使用官方总数和分页参数；保留无摘要的真实搜索结果，不能先丢掉部分条目再伪装成整页或提前结束。报告生成时另行判断证据是否足够。
- 超过来源可访问页数时禁用下一页并给出提示，不捏造任意深度的分页能力。
- 中文提示、429 限流提示、部分来源失败 warnings 沿用现有处理。
- 扩展搜索响应的 page、page_size、total、has_next、sort、used_source 与论文引用数字段。旧的限量检索调用保留兼容，研究工作流的 search 协议不被页面分页需求破坏。

官方依据：

- https://help.openalex.org/api/sorting/
- https://help.openalex.org/api/paging/
- https://info.arxiv.org/help/api/user-manual.html

## 学习报告入口与任务

- 收藏夹页面增加“生成学习报告”，提供勾选、全选和已选数量；每篇论文旁可直接生成单篇报告。
- 一次选择同一收藏夹中的 1 至 20 篇论文；默认不强制选满。多篇合成一份 DOCX，内部保留逐篇分析与跨论文总结。
- 创建页可填学习目标和补充体会，空白时由 Agent 给出建议性学习体会。
- 创建时 Java 校验收藏夹及所有论文归属，并保存论文资料、已保存笔记、用户学习目标的快照。用户后来编辑或移除收藏不改变历史任务。
- 新任务类型 study_report 与原 research 区分，使用现有排队、持久化、超时、用户隔离和幂等请求机制；默认旧任务类型保持兼容。
- 页面展示获取证据、逐篇分析、综合整理、报告就绪的进度。生成失败可查看原因，不返回模板冒充成功。
- 历史页区分研究任务和学习报告；完成后可打开报告和下载 Word。

## 报告内容

报告标题、生成时间、论文清单与来源链接之后，为每篇论文生成：

0. 论文概述：研究目标、核心思路和主要结论的简短说明。
1. 研究背景与问题：研究动机、已有方法不足、论文解决的具体问题。
2. 模型方法（模块解释）：整体流程、各模块的作用、输入与输出，以及模块之间如何连接；非模型论文按实际方法步骤解释，不强行发明模型模块。
3. 创新点与实验结果：贡献、数据集、比较基线、指标、关键结果和消融结论。正文未提供或未获取到的数字不生成。
4. 学习体会：Agent 根据论文和用户笔记整理可学到的知识、理解难点、局限、复现建议和下一步学习计划。没有个人笔记时不声称用户亲自完成了实验或已经掌握某技能。

多篇报告额外增加方法对比、共同结论与差异、建议学习顺序。结尾附参考论文和证据定位；论文结论与 Agent 的学习建议应有清楚区分。

## 正文与 Agent

用户已选择：自动尝试获取开放 PDF 并解析，沿用现有证据块、页码和上下文预算能力。失败或无 PDF 时明确显示原因及对应论文，提示补充可公开访问的 PDF 链接或正文笔记后重新提交；不得静默回退摘要并宣称已阅读全文。用户可在后续显式选择仅依据摘要生成初步报告，不能自动替用户作此选择。暂不新增文件上传系统，补充入口复用论文资料编辑与笔记。

若用户明确选择摘要模式，缺少的模块细节与实验结果明确标注待核实。

新增学习报告的结构化输出模型和 Agent 指令，避免把已有“研究构思”字段机械改名。逐篇分析后进行多篇综合，并校验返回的论文标识和证据引用均来自当前任务。模型调用只在 Python 执行，复用现有 Qwen / OpenAI 配置。

真实模式必须调用真实模型；离线演示需明确标注，只用于流程验证，不能无声回退。模型未配置、获取证据失败、解析失败、部分论文分析失败均需可见，报告不得悄悄遗漏所选论文。

## DOCX 导出

- Python 根据已保存的结构化学习报告使用 python-docx 排版；导出本身不再次调用模型，也不重新抓取论文。
- Java 提供需要登录和任务归属校验的下载接口，转发内部文档响应；浏览器不直接访问 Python 服务。
- 返回标准 DOCX MIME 和安全的下载文件名。仅报告完成后可导出，不能由浏览器传任意路径读取文件。
- 使用中文正文与标题样式、层级标题、适当分页；多篇时每篇有清楚边界，避免复杂大表导致跨页溢出。
- 在线报告与 Word 来自同一份报告快照，内容一致，历史任务在服务重启后仍可下载。

## 边界与验收

- 搜索测试覆盖两个来源的参数映射、总数、不同页内容、排序、来源固定、未知引用数、无摘要结果、限流、超界与旧接口兼容。
- Java 验证登录、CSRF、收藏夹/论文归属、任务幂等、历史快照、下载权限及 DTO/VO 契约。
- Agent 使用可控测试模型验证单篇、多篇、结构完整、模块解释、证据不足、模型故障和报告引用校验；真实模型验证需要现有可用凭证，不能用演示测试冒充。
- 浏览器验收搜索排序与翻页、收藏、选择论文、提交学习报告、任务状态、预览和 DOCX 下载，以及桌面与手机布局。
- DOCX 验证 ZIP/XML 内容和中文样式，生成代表性单篇与多篇样本，渲染后逐页检查裁切、分页、表格和字体。
- 不改动已有普通研究报告结构，不引入 Java 多模块、JPA 或新的微服务部署要求。
