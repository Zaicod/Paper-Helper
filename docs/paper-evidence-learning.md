# 正文准备、默认主题与失败任务修复

## 解决的问题

过去，收藏记录即使没有 PDF 地址，也能提交全文学习报告；任务运行后才发现无法获取正文。修改收藏资料再点重试，仍会使用原任务的旧资料，所以同一个错误会反复出现。

现在把正文检查提前：先准备并解析 PDF，状态就绪后再创建全文学习报告。摘要、笔记和 DOI 页面不能替代 PDF 正文。

## 如何使用

1. 在收藏夹找到论文，点击准备正文。系统先尝试已有 PDF 地址，再通过论文身份匹配查找开放 PDF。
2. 找不到或网站阻止访问时，上传你已获取的 PDF。支持不超过 25 MiB、200 页且能提取文本的 PDF；扫描版没有 OCR，无法提取正文时会提示不可读。
3. 选中论文创建研究，表单自动填写下面的默认主题。可以直接提交、修改，或恢复默认主题。全文学习报告需所有选定论文的正文都就绪。
4. 旧任务失败后，先修复收藏中的资料并准备正文，再使用“修复资料后重新创建”。它使用当前资料和模型设置创建新任务，保留原失败记录。

默认主题：

> 请基于所选论文，分析研究背景与解决的问题、核心创新点、模型总体架构及各模块作用、实验设置与主要结果、局限性，以及可改进的方向。对正文未提供的信息明确标注，不补造细节。

此默认值适用于选定论文的研究；按主题搜索仍需输入实际研究方向。额外学习目标为空时，逐篇分析 Agent 也会收到研究主题；填写了学习目标则优先采用该目标。

“沿用原输入重试”继续使用原来的论文和正文版本；“修复资料后重新创建”重新读取当前资料。修改论文资料会使原准备状态失效，需要重新准备。

## Java 与 Agent 怎样协作

浏览器只向 Java 发送业务请求。Java 验证账号与收藏归属，再调用 Python 内部接口上传、准备或读取文件。准备过程不调用大模型，网络与文件解析在 Java 数据库事务之外进行。

Python 检查文件类型、大小、页数和正文，保存 PDF 与提取片段，生成不可变的文档编号。远程地址继续执行公开 HTTPS、DNS 和重定向检查。开放 PDF 查询会核对 DOI 或来源编号，不能只凭相似标题替换论文。

Java 保存账号、收藏论文、资料指纹和文档编号之间的关系。新全文任务提交时再次确认资料未变化且正文就绪，将每篇论文对应的文档编号写入任务快照。Python 按账号命名空间、论文指纹和文档编号读取对应版本；正文版本也参与检索缓存标识，避免更新 PDF 后继续使用旧证据。

上传文件不是公开附件。PDF 下载接口检查当前登录账号，历史任务仍可引用旧版本。修复操作创建新记录并支持幂等处理，不会改写旧任务历史。已有的旧任务保留原来的直接获取 PDF 路径。

## 从哪些代码学习

- `java-backend` 中的 `PaperDocumentController`、`PaperDocumentService`、`PaperDocumentMapper`：权限、业务规则、持久化与外部服务调用。
- `paper_agent/tools/prepared_documents.py`：文件验证、账号隔离、不可变版本、开放 PDF 解析与准备状态。
- `paper_agent/interfaces/worker.py`：内部服务认证、上传接口、请求大小限制与任务接入。
- `paper_agent/services/study.py`：准备好的正文如何进入检索、逐篇分析和报告合成。
- `frontend-vue/src/components/PaperDocumentControl.vue`：准备、上传、状态提示与提交前检查。

重点理解两种快照：收藏资料代表用户当前想研究什么，任务快照代表某一次运行实际使用了什么。把它们分开，才能解释历史结果并可靠地修复任务。

## 验证与适用范围

本轮验证包含 Python、Java 和 Vue 测试、前端构建、桌面/移动端浏览器流程，以及打包后的 Java 与真实 Python PDF 解析联调。联调使用临时数据库、生成的 PDF 和模型替身，覆盖上传、默认主题、失败后修复、版本保留与账号隔离，没有调用个人模型密钥。

MMSTG-Net 的原任务没有 PDF 地址；本轮没有取得该论文可验证的公开 PDF。新流程提供提前检查和上传入口，并不保证每篇论文都能自动找到正文；这篇论文仍需可访问的 PDF 或用户提供的文件。

代码已在本地实现。本轮未同步 GitHub，也未重启原来运行的服务；使用新功能需要按项目启动方式重新构建并启动新版 Java、Python 与前端。Java 启动时由 Flyway 应用 V5 文档登记表迁移。
