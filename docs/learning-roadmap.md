# 面向实习的学习路线

目标不是只会调用一次模型，而是能够在面试中解释：任务为何拆分、状态如何流转、工具与 Agent 有何区别、如何测试和评估。

## 阶段 0：跑通与阅读（1—2 天）

- 跑离线演示并查看 Markdown、JSON 输出。
- 沿 README 的顺序阅读代码。
- 手画一次数据流图，说明哪些步骤可并行、哪些必须串行。
- 修改一个输出字段，并让整个项目与测试重新通过。

验收：能脱离代码，用 3 分钟解释系统架构。

## 阶段 1：真实 Agent MVP（2—4 天）

- 配置 API Key，运行 3 篇论文的真实分析。
- 在 Trace 中观察模型调用、延迟和失败。
- 比较两个 Prompt 版本，记录哪类字段更可靠。
- 为 arXiv 超时和空结果增加清晰错误。

验收：能解释 Agent、工具、结构化输出、编排器各自解决的问题。

## 阶段 2：全文 RAG（5—7 天）

- 下载 PDF，提取正文与页码。
- 按章节和 token 长度切块。
- 使用 embedding + 向量库召回证据片段。
- 报告中的结论附论文、页码与原文片段。

验收：用一组人工问题评估召回率和引用忠实度，而不是只看“回答像不像”。

当前进度：PDF、分块、Embedding、向量检索、上下文预算和 chunk 引用已经实现；下一步是建立检索标注集并计算 Recall@k/MRR。

## 阶段 3：更强的多 Agent 协作（3—5 天）

- 查询规划 Agent 生成同义词、子主题和排除词。
- 评审 Agent 对分析和创新想法打分，不达标则反馈重写。
- 对比代码编排、manager-as-tools、handoff 三种方式。
- 增加并发上限、重试、缓存与断点恢复。

验收：能够根据确定性、灵活性、延迟、费用选择编排模式。

## 阶段 4：工程化与作品集（5—7 天）

- 增加 FastAPI 后端与简单前端。
- 保存项目、运行记录和用户反馈。
- 添加日志、token/费用统计、失败告警。
- 建立 20—50 个样例的自动评测集并在 CI 中运行。
- README 补充架构图、演示 GIF、指标、已知限制和未来路线。

验收：作品能部署、能复现、能量化质量，也能诚实说明边界。

当前进度：MCP Server、HTML 输出、人工评测和奖励轨迹已完成；FastAPI/Web UI、数据库任务状态和部署仍待实现。

## 推荐的面试叙述

“我先用代码编排构建确定性 MVP，把检索做成工具，把需要语义推理的步骤做成专职 Agent。各 Agent 通过 Pydantic 结构化输出通信，逐篇分析并发、跨论文总结串行。之后我加入全文 RAG、证据页码、评审循环与离线评测，用引用忠实度和检索召回率衡量效果，而不是只靠主观观感。”
